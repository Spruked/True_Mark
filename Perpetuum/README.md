# Perpetuum — Account Holder Workspace

An isolated desktop application for a signed-in account holder to organize, parse, encrypt, and package knowledge and heirloom material locally. This workspace does not mint tokens, generate certificates, pin to a decentralized network, or duplicate any downstream issuance system.

## Architecture

- **Tauri + Rust**: account-scoped local encryption, content hashing, and SQLite ledger operations.
- **React + TypeScript + Vite**: Perpetuum ingestion timeline and package review UI.
- **ChaCha20-Poly1305**: authenticated encryption. The output format is `12-byte nonce || ciphertext || Poly1305 tag`.
- **SQLite**: local audit ledger with asset type and storage-provider constraints.
- **Optional local parser**: `processor/organizer.py` extracts document structure and media metadata before encryption.

## Account workspace boundary

Each signed-in account holder gets a separate workspace key. Native storage is partitioned as:

```text
application-data/
└── workspaces/
    └── <account-workspace-id>/
        ├── organizer.db
        └── encrypted/
```

The workspace ID must come from the signed-in account context. It is not derived from a display name. Use a stable, non-secret account identifier and keep authentication in the host application.

## Run

Prerequisites: Node.js 20+, Rust stable/Cargo, Tauri system dependencies, and optionally Python 3.11+ with FFmpeg.

```bash
npm install
npm run tauri:dev
```

For browser-only UI work:

```bash
npm run dev
```

Build and test the native layer:

```bash
cd src-tauri
cargo check
cargo test
```

Run the optional organizer:

```bash
python3 processor/organizer.py ./my_local_workspace --output ./processor-output
```

## Security boundaries

- Never commit encryption keys, wallet keys, API credentials, or source archives.
- A 32-byte key is required for ChaCha20-Poly1305 commands.
- Nonces are generated by the Rust runtime for every encryption operation.
- The ledger stores paths, hashes, nonce metadata, and storage references; it does not store the encryption key.
- External storage and transfer are not silently enabled.
- Workspace deletion, account deletion, and key recovery need an explicit product policy before production use.
